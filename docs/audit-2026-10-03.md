# Release audit: October 3, 2026

The audit covered public browsing, listing visibility, ingestion, scoring,
contributions, editorial concurrency, auth gates, affiliate redirects, dependency
security, migrations, and deployment. It includes the uncommitted UI, photo,
font, validation, and migration work present at the start of the audit.

## Corrections

- Reports, evidence, review flags, and scores commit together. Recalculation
  failures roll back the report, allowing a retry. Listing locks prevent concurrent
  duplicates and stale editorial/scoring writes.
- Public details enforce active launch-city and evidence rules. Unverified rows
  with cooling signals remain eligible even without a written summary. Seed
  fallback visibility also requires cooling-related excerpts when there is no
  summary or editorial endorsement.
- Manual imports retain non-cooling reviews for audit without projecting them
  into Guest Signal. Text-based broken penalties require negative sentiment.
- Forwarded IPs require explicit proxy trust and valid addresses. Production
  affiliate destinations reject loopback hosts and embedded credentials.
- Report and editorial forms recover from failed network requests. Detail pages
  and the formula page use their own canonical URLs and metadata.
- MapLibre workers are served from the application origin. Browsing stays usable
  when WebGL is unavailable, and browser tests require successful map loading.
- Production environment validation requires storage and an HTTPS origin.
  Railway runs validation and migrations before starting the service and checks
  database health. CI now exercises a disposable PostgreSQL database.
- Deployed smoke tests discover real listing IDs and perform read-only checks.
  Local write tests are no longer selected for an external deployment URL.

## Dependency review

Patched Next.js, its lint configuration, Auth.js, its Drizzle adapter, MapLibre,
Nodemailer, CSV parsing, and affected transitive dependencies. The production
audit changed from 6 critical, 16 high, and 17 moderate advisories to zero.
The lockfile passes pnpm 11.7.0's release-age checks.

Vitest and the vulnerable lint-tool transitive dependencies were also patched.
The full audit retains two development-tool advisories: `braces` (high, no
published patched release) and the legacy `esbuild` used by Drizzle's tooling
(moderate). The former requires malicious glob input; the latter requires an
exposed development server, which migration and production commands do not run.
Neither appears in the production dependency audit.

Next.js publishes the relevant [image-response advisory](https://github.com/vercel/next.js/security/advisories/GHSA-vcvr-r3jv-pc5j).
The installed application overrides the email provider's sender with its existing
Resend implementation; Nodemailer 10 is an explicit peer compatibility allowance
for patched package loading. SMTP delivery remains outside the tested launch path.

## Verification

- Strict seed validation: 6 listings, all evidence-backed.
- TypeScript and ESLint: passed.
- Unit and integration suite: 128 passed; 6 database tests skipped without a URL.
- PostgreSQL suite: all 6 passed with a disposable PostgreSQL 16 database.
- All migrations and seed import succeeded on the fresh database.
- Score-refresh command completed for all 6 listings.
- Production build: passed.
- Browser suite: 14 passed; the auth-enabled scenario is deliberately skipped for
  the auth-disabled launch. Includes network failure recovery and missing WebGL.
- Production dependency audit: zero reported vulnerabilities.

## Operational limits

- Public launch keeps authentication disabled. Live magic-link delivery and
  authenticated browser workflows require email configuration and separate QA.
- IP throttling is disabled until ingress header sanitation is verified. Cookie
  duplicate protection does not establish a unique person.
- Existing databases must run `pnpm signals:recompute` after this scoring fix.
  The command also recovers scores after an extraction job saves classifications
  but fails during recomputation. Extraction retries alone skip cached evidence.
  Recalculation does not repair old manual-import classification errors. Any
  existing non-cooling excerpts previously marked as cooling require a separate
  classification repair. The new production database starts with current logic.
- Six Lisbon listings remain the launch inventory. Licensed photo URLs are
  optional and missing images use the existing placeholder design.
- Connecting `mintystays.com` requires the correct DNS records. Use the deployed
  Railway origin as canonical until the custom domain is configured.
